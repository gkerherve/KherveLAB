# CLAUDE.md — working conventions for KherveLAB

KherveLAB is a desktop app (Python 3.11+, PyQt6) for booking shared
instruments. Shared state is a Git repository of plain YAML files. It
follows the KherveLab build plan, and all of its phases (0 to 7) are built:

- 0: Git sync
- 1: calendar
- 2: published site
- 3: GitHub requests
- 4: encrypted training records
- 5: logbook
- 6: samples and the data index
- 7: reports and notebook API

## Branching

Work goes on `dev`. `main` is the stable branch and is only merged into when
the user asks. Commit and push after every change. Add specific files, never
`git add -A`.

## Version

`khervelab/__init__.py` holds `__version__ = "<major>.<minor>"`. Bump the
minor version in the same commit as any change the user can see. Bump the
major version only when asked.

## Architectural rules

- `khervelab/core/` imports no Qt. The config loader, the rules engine
  (`schedule.py`), the Git layer (`repo.py`) and `facility.py` are pure
  Python over dataclasses. If a function needs a widget to be tested, it is
  in the wrong package.
- All Git access goes through `core/repo.py`. Never call `subprocess git`
  from the UI.
- Every booking mutation is one commit, with a message such as
  `book xps 2026-10-07 09:00-13:00 u-0001`.
- Fail loudly on invalid YAML. The error names the file and the key at
  fault, and a booking is never silently skipped.
- No personal data in the repository. Users are anonymous ids, and the
  commit guard refuses anything that looks like an email address.
- Timezones are explicit. Store times as ISO 8601 with an offset, and do
  duration and overlap arithmetic in UTC (see `models._utc`).
- Personal data (names, emails, training, evidence) lives only in
  `khervelab/local/store.py`'s encrypted SQLite. Never write it to the repo.
- The data index (`local/dataindex.py`) is local, never shared.
- The published site goes to `docs/` (Pages serves only `/` or `/docs`).
- The instrument catalogue is generated by `tools/build_catalogue.py`.
  Edit it there and regenerate; do not hand-edit the template YAML.

## Tests

Before committing, run `.venv/bin/python -m pytest -q` (set
`QT_QPA_PLATFORM=offscreen` when there is no display). Any change to `core/`
needs matching tests in the same commit.
